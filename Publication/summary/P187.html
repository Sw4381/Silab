LogRESP-Agent: 문맥 인식 로그 이상탐지와 TTP 분석을 위한 재귀적 AI 에이전트 프레임워크

LogRESP-Agent: A Recursive AI Framework for Context-Aware Log Anomaly Detection and TTP Analysis

이주영 · 정연수 · 한태현 · 이태진(교신) 가천대 Applied Sciences 15(13), 7237 (2025)SCIE DOI: 10.3390/app15137237 2025.06.27 게재 (접수 05.31 · 승인 06.24)

핵심

템플릿 파싱 없이 이종 엔드포인트 로그를 LLM이 직접 읽고, 계획형 LLM 에이전트(Gemini-2.0-Flash)가 7개 도구(규칙·이상점수·문맥 RAG·TTP 매핑 등)를 상황에 맞게 골라 호출하는 재귀 TAO(Thought–Action–Observation) 루프로 탐지 + MITRE ATT&CK 근거 설명까지 자동 생성

99.97%Monster-THC 이진 이상탐지 정확도 (FPR 0.0)
0.97Monster-THC 평균 F1 (AE +15pp · LogBERT +14pp)
99.47%EVTX-ATTACK 8개 전술 다중분류 F1 (정확도 99.54%)
−4.01%RuleMatcher 제거 시 F1 하락 (ablation 최대)
10–15s로그 1건 전체 추론 주기 (도구 호출당 1–5s)

①문제의식

  • Q1 이종·비정형 로그: 벤더·도구마다 필드명·스키마·상세도가 달라 DeepLog·LogBERT류의 고정 어휘·템플릿 파싱은 의미 손실·일반화 실패, 다중 출처면 재학습·수동 정규화 필요
  • Q2 해석 불가: 대부분 이진 라벨·점수만 출력 — 실무자 80%+가 설명 없는 경보엔 조치를 주저(Ma et al.), 시간·출처 간 상관 없이 시퀀스를 고립 처리
  • Q3 정적·수동 추론: 단일 패스 추론, 외부 검색·다단계 추론·목표 계획 없음. IDS-Agent·SERC 같은 LLM 시스템도 고정 도구 파이프라인·정적 프롬프트라 가설 수정·재귀 불가

④평가 데이터 · 설정 (2종 · 2과제)

  • Monster-THC(이진): 실기업 Windows 환경 Monster Agent 프로세스 생성 이벤트(ID 1500), Chrome·Edge·Hwp — 33,559건(정상 33,272 / 악성 287, Execution·권한상승·방어회피 등). 산업체 제공, 비공개
  • EVTX-ATTACK-SAMPLES(다중): 공개 Windows 공격 evtx → CSV, MITRE ATT&CK 전술 라벨 — 악성 3,167건 · 8개 전술(C2·권한상승·측면이동 등)
  • 설정: 80/20 분할(클래스 비율 유지), 교차검증 없음, 지표 TPR·FPR·Acc·F1, Welch t-test 5회 독립 실행
  • 비교: 비지도 AE·LogBERT(이진) / MLP·RF·XGBoost(다중) / 에이전트 변형: SequenceScorer를 LogBERT(이진) 또는 RF·XGBoost(다중)로 교체

③제안 방법

  • 입력·목표: 사용자/시스템 목표(예: “process A 악성 여부”)에 해당하는 로그를 읽어 의미 기술 D 생성 — 프로세스명·부모 계보·경로·권한 수준·실행 문맥 추출(템플릿 파싱 없음)
  • Planning(Thought): LLM(Gemini-2.0-Flash, LangChain 기반)이 도구별 효용 = 목표 관련성 + 기대 정보이득을 각 5점 척도로 직접 채점해 최고 도구 선택 (수식 아닌 LLM 문맥 추론 — 휴리스틱)
  • 7개 도구(Action): LogLoader · DescriptionGenerator(자연어 요약) · RuleMatcher(알려진 악성 지표) · SequenceScorer(LogBERT 이상점수 / RF·XGBoost 다중분류) · ContextRetriever(과거 로그·프로세스 계보 RAG) · TTPMapper(ATT&CK 기법) · ThreatLookup(위협정보 DB)
  • Reasoning(Observation)·재귀: 결과를 단기 메모리(ObservationList)와 전역 추론 추적(ThoughtHistory)에 누적 → 신뢰도 기반 충분성 판단, 부족하면 Planning으로 복귀. 규칙 미매치 시 ContextRetriever로 피벗, 이상점수·TTP·계보가 동시 수렴하면 조기 종료
  • 최종 출력 E: Summary(정상/의심/공격) · Evidence · Reasoning Trace(도구 호출 순서·단계별 결론) · Mapped Threat Context(ATT&CK 전술·기법)
  • 운영: 비지도 탐지기는 재학습 불필요(분포 급변 시 선택), 규칙·문맥·TTP·위협정보 도구는 핵심 모델과 독립 갱신. 외부 API LLM 사용으로 로컬 메모리 부담 최소

  • 사례 #30048(THC 악성): 샌드박스 해제 Chrome → PowerShell 숨김 실행 → msgbox.exe 다운로드 → cmd.exe 상승 명령; RuleMatcher(-ForceV1·ComputerDefaults.exe·SeChangeNotifyPrivilege) + 계보 복원 → T1202·T1548 매핑, 정답 일치
  • 사례 #441(EVTX Cred. Access): w3wp.exe → PowerShell(-nop -noni -enc, Temp 경로) → appcmd.exe list vdir /text:password → RF 분류 ‘Credential Access’ + T1552.001·T1027
  • 사례 #1671(정상 Chrome): 규칙·점수 모두 정상, ContextRetriever가 Slack→Chrome 실행 계보 확인 → 오탐 회피
해석 시 주의: 탐지 점수 자체는 기존 모델(LogBERT / RF·XGBoost)을 SequenceScorer로 품고, 에이전트가 규칙·문맥·TTP 신호를 재귀적으로 결합해 얻는 이득 — 다중분류는 XGBoost 단독 98.02→98.96%. 로그 1건당 10–15s라 실시간 탐지가 아닌 triage·조사 용도. 설명 품질은 사례 3건 정성 분석만, 구조화된 사람 평가 없음

⑥한계 · 향후

  • 탐지·설명까지만 — 방화벽 규칙·호스트 격리 등 자동 대응 없음 / 제로데이·적대적 로그 조작에 대한 강건성 미평가(향후 회피 공격 시뮬레이션)
  • 도구 선택이 LLM 5점 휴리스틱 → 학습형 효용 모델로 대체 예정 / 성능이 RuleMatcher·SequenceScorer 등 개별 도구 품질에 종속
  • Monster-THC 비공개(산업체 계약), 교차검증 없음, 평가 LLM 1종(Gemini-2.0-Flash) / 향후 포맷 무관 로그 정규화 모듈(EDR·SIEM·클라우드), 다국어 로그, 분석가 피드백 기반 설명 평가
