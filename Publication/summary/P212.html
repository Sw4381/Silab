Automated Identification and Interpretation of Anomalous Cases in Industrial Control Systems

이선우 · 임승범 · 이태진(교신) 가천대 (임승범: SANDS Lab) Electronics 15(12), 2705 (2026)SCIE DOI: 10.3390/electronics15122705 2026.06.16 Accept · 06.18 Published

핵심

GDN 탐지기 위에 얹는 탐지기 독립 후처리 계층: Top-10 상관 센서 중 이상 센서 수를 동적 임계값 스무딩 전·후로 세어 “장애는 결합 센서가 함께 이상, 공격은 고립”이라는 상관관계 유지 여부를 정량화 → 탐지 이상을 장애·공격·오탐·미탐으로 자동 분류하고 상관 그래프·히트맵·영향 센서 그래프로 전파 경로를 해석

①문제의식

  • 이상 유형 미정의: 환경 변동으로 자가 복구되는 장애(fault)와 센서값을 조작해 지속·치명적 영향을 주는 공격(attack)이 하나의 “anomaly”로 뭉뚱그려져 모든 탐지를 동일하게 triage → 가용성 우선 ICS에서 비효율
  • 정확도–오탐 트레이드오프: recall↑ → FP↑ → 전문가 검토 길어지고 조치 지연. 임계값 자체를 조정하는 대신 임계값 부근 모호 판정을 집어내는 도구가 없음
  • 시계열 XAI 한계: SHAP·LIME은 센서별 독립 기여도·단일 시점 설명 → 상류 pH 센서 AIT202 조작이 AIT402·FIT301로 전파돼도 셋을 비슷한 중요도로 나열, 근본 원인 센서를 못 짚음
  • 공통 신호: 세 문제 모두 “판정 시점 주변 센서 공변”(Top-K 상관 그래프 + 스무딩 전후 이상 센서 수)에서 읽힘 → 별도 과제가 아닌 단일 후처리 프레임워크로 동시 해결

④평가 데이터 · 설정 (SWaT)

  • SWaT(iTrust·SUTD 수처리 테스트베드, 51속성, 초 단위): 학습=정상 991,800 인덱스(≈275.5h) / 테스트=36개 이상 시나리오 449,909 인덱스(≈125h; 실제 이상 54,621·정상 395,288)
  • 탐지기: GDN, 학습:검증 8:2, Top-K 5/10/15 비교 → K=10 채택(F1 0.787, 5시드 반복으로 안정성 확인). 테스트 판정: 이상 40,491(TP 37,426·FP 3,065) / 정상 409,418(FN 17,195)
  • 유형 임계값(센서 수, K=10): 장애 후≥3 · 공격 후 1–2 · FP 후=1 · FN 전=10 & 후≥5. 탐지 임계값은 경험적 보정(최적 ≈91 백분위), 윈도우 크기·Top-K 민감도 별도 분석
  • 환경: Xeon Gold 6226 · 128GB · Tesla T4 16GB · Python 3.11.5

③제안 방법

  • 기반 탐지기(GDN): 센서 임베딩 → 코사인 유사도로 시점별 Top-K(=10) 상관 서브그래프 → 그래프 어텐션으로 각 센서 예측 → 센서별 |실측−예측| 오차를 중앙값·IQR로 정규화 → 집계 점수 > 임계값이면 이상. 표준 기법이며 기여 아님
  • 동적 임계값 스무딩: 센서별 임계값을 학습·테스트 데이터의 휴리스틱 임계값 평균(상위 분위수 근처)으로 두고 오차 점수를 스무딩 → 일시적 스파이크 억제. 스무딩 전·후 Top-K 중 이상 센서 수를 각각 집계
  • 상관관계 유지 비율: Top-K는 서로 가장 상관된 센서 집합이므로 “스무딩 후에도 이상인 센서 수(ρpost)”가 상관 유지의 계산 가능한 대리 지표 — 장애는 결합 센서가 함께 이상(높음), 공격은 고립(1–2개로 붕괴). 쌍별 상관값은 별도 임계값 없이 히트맵으로 제시
  • 4유형 판정 규칙(Table 1): 탐지=이상 → 후 count 높음=장애 / 낮음=공격 / 최저(1개)=FP 후보(공격 풀의 부분집합); 탐지=정상인데 전·후 모두 높음(전 10·후≥5)=FN 후보
  • 해석 5요소: Top-10 센서 err 점수·이상 여부 / 핵심 센서 서브그래프 / 상관 히트맵(빨강 높음·파랑 낮음) / 영향 센서 그래프(빨강 flagged·파랑 추가 관심·초록 유입) / 정상 구간 대비 실측값 비교 → 장애는 원인 센서+인접 센서 체인, 공격은 하류 영향 센서를 좁힘
  • 탐지기 독립: 후처리 계층 입력은 이상 플래그·센서별 오차·학습 그래프뿐 → 다른 상류 탐지기로 교체 가능. 분류는 post hoc라 탐지 지표를 바꾸지 않음

  • 장애/공격 분리: 이상 판정 40,491 중 장애 35,913(후≥3) vs 공격 4,578(후 1–2) = 88.7 : 11.3. 장애 풀은 자동 제어기가 흡수하는 일시 편차 위주 → 전문가는 소수 공격 풀에 집중, FP 후보 328건도 이 공격 풀에서 추출
  • Case 3 공격(t=7,229): 전 9개 이상 → 후 AIT402·FIT301만 잔존, 히트맵 대부분 파랑(저상관). 데이터셋 주석: AIT202(pH) 조작 → 액추에이터 P203 → AIT402·FIT301 즉시, PIT502·AIT504는 약 2h 후 영향 — 영향 그래프가 전파 경로와 일치, 센서값 비교에서 AIT202만 급락(근본 원인)
  • Case 4 장애(t=348,322): 히트맵 대부분 빨강(고상관), 후 6개 잔존(P203·MV302·FIT301·P302·MV101·P205) — 주석의 P302 조작 장애·예상 전파와 일치
  • Case 1 FN(t=436,577): 모델은 정상 판정이나 전 10개·후 5개(PIT501·PIT503·FIT503·FIT504·MV304) 잔존 → 주석 P501·FIT502 조작 장애 복구. Case 2 FP(t=264,349): 후 P201만 잔존, 저상관, 실측값이 정상 분포와 일치 → 오탐 확인
  • 민감도: 채택 윈도우·Top-K 근방에서 F1 변동 수 포인트 이내, 탐지 임계값 최적 ≈91 백분위 — 다른 ICS에선 재보정 필요

⑥한계 · 향후

  • SWaT 단일 데이터셋 검증 — WADI·HAI·운영 ICS 미검증 / 탐지 임계값·유형 컷오프 모두 경험적 보정 → 환경별 재보정 필요(자동 적응은 향후 과제)
  • 상관 가정의 경계 사례: 여러 센서를 협조 조작하는 은밀 공격은 장애로, 단일 센서 국소 장애는 공격으로 오분류 가능 → 시간 패턴·액추에이터 명령 로그·공정 단계·물리 규칙으로 보완 예정
  • 정밀도 83%/73%는 기반 탐지기 품질에 종속 / 수백~수천 센서 규모는 시점별 그래프 구성 최적화 필요 / 해석 평가는 사례·시각물 중심(정량 해석성 지표 부재)
